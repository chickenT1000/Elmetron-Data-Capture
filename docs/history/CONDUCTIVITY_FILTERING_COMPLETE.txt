2. BACKEND FILTERING (API)
================================================================================

Location: data_api_service.py

New Function: filter_conductivity_by_rate_of_change()
  
  How it works:
  1. Calculates rate of change between consecutive measurements
  2. Rate = |value_diff| / time_diff (µS/cm per second)
  3. Filters out measurements where rate > threshold
  4. Keeps first measurement always
  5. Preserves temperature and other parameters
  
  Algorithm:
  - For each measurement i (starting from i=1):
    * Calculate: rate = |conductivity[i] - conductivity[i-1]| / time_diff
    * If rate > threshold: Set conductivity to null (filter it)
    * Else: Keep the measurement
  
  Benefits:
  - Only hides data during rapid changes (polarization)
  - Shows data as soon as signal stabilizes
  - Doesn't remove sustained changes (real concentration shifts)
  - Prevents chart scaling issues from transient spikes

API Endpoints Updated:
  - /api/sessions/<id>/measurements
  - /api/measurements/recent
  
  New Query Parameters:
  - filter_conductivity: 'true' or 'false' (enables filtering)
  - filter_sensitivity: 0-100 (logarithmic scale)

4. HOW IT WORKS (USER PERSPECTIVE)
================================================================================

When Electrode is Immersed (Polarization Event):
  1. Conductivity starts changing rapidly (e.g., 200 µS/cm/s)
  2. Rate exceeds threshold (e.g., 31.6 µS/cm/s at sensitivity=50)
  3. Conductivity values are hidden (set to null)
  4. Chart doesn't show wild spikes
  5. Temperature, pH, Redox continue to display normally

When Signal Stabilizes:
  1. Rate of change drops below threshold (< 31.6 µS/cm/s)
  2. Conductivity values start appearing again
  3. Chart shows stable readings
  4. Normal measurement continues

Adjusting Sensitivity:
  - Lower (0-40): Fast response, shows data sooner, some spikes may appear
  - Medium (40-60): Balanced - recommended for most cases
  - Higher (60-100): Very stable, waits longer for signal to settle

6. LOGARITHMIC SCALE EXPLAINED
================================================================================

Why Logarithmic?
  - Conductivity changes span wide range (1 to 1000+ µS/cm/s)
  - Linear scale would be too coarse at low end, too fine at high end
  - Logarithmic provides even adjustment across all ranges

Mapping Formula:
  threshold = 10 ^ ((slider_value / 100) * 3)

Examples:
  Slider | Calculation      | Threshold   | Description
  -------+------------------+-------------+------------------------
  0      | 10^((0/100)*3)   | 1 µS/cm/s   | Very permissive
  10     | 10^((10/100)*3)  | 2 µS/cm/s   | Permissive
  25     | 10^((25/100)*3)  | 5.6 µS/cm/s | Loose
  50     | 10^((50/100)*3)  | 31.6 µS/cm/s| Medium (default)
  75     | 10^((75/100)*3)  | 178 µS/cm/s | Strict
  90     | 10^((90/100)*3)  | 501 µS/cm/s | Very strict
  100    | 10^((100/100)*3) | 1000 µS/cm/s| Maximum stability

9. ADVANTAGES OVER PREVIOUS APPROACH
================================================================================

Old Approach (Magnitude-based outlier detection):
  ✗ Filtered based on absolute values (IQR, MAD)
  ✗ Could filter real polarization data (2-second events)
  ✗ Static thresholds didn't adapt to different solutions
  ✗ No user control

New Approach (Rate-of-change based):
  ✓ Filters based on how fast signal changes
  ✓ Keeps sustained changes (real measurements)
  ✓ Only hides rapid transients (polarization spikes)
  ✓ User-adjustable sensitivity
  ✓ Adapts to different measurement scenarios
  ✓ Shows data as soon as stable
